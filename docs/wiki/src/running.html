Security

40.1 The model

LayerControl
TransportHTTPS throughout; HSTS with a two-year max-age and preload.
SessionSupabase Auth. Role and silo in JWT app metadata, which the client cannot alter.
RouteMiddleware evaluates the route matrix; unauthorized → /403.
RowRLS on every table. Deny by default, then explicit policies.
Functionrequire_role() opens every privileged mutator; EXECUTE revoked from anon.
RatePer-user limits on routes that cost money or third-party quota.

40.3 Rate limiting

BucketLimitRationale
chat40 / minA person types perhaps 6 a minute; a render loop types 600.
geocode120 / minFires per keystroke-batch on the address field.
external90 / minMetered upstreams; panels poll on a timer.
pdf20 / minEmbedding photographs is the most expensive request served.
ptt60 / minRadio traffic is bursty.
cctv60 / minEach grant is audit-logged; a flood pollutes the trail.

Counted in Postgres because the console deploys serverless — an in-memory counter is per-instance, and ten concurrent functions would mean ten times the limit. Identity comes from auth.uid() inside the database function, so a handler cannot get it wrong and a caller cannot spend somebody else's budget.

It fails open If the limiter errors, the request proceeds. A rate limiter that takes down dispatch when the database hiccups causes more harm than the runaway loop it guards against.

If an operator hits a 429 in normal work, the limit is wrong, not the operator. Raise it in apps/web/lib/rate-limit.ts and deploy. To clear one person's counter: 

delete from rate_limit_buckets where key like 'chat:%<user-uuid>';

40.4 Outstanding items

Open, and to be closed before or at handover
  • Legacy credentials. The superseded system's BulkSMS token pair and Gemini key are in that repository's source history, including a hardcoded token in its notifications controller. They must be revoked at the provider — rotating them here does not help, because the old values remain in that repository’s history.
  • Setup-time exposure. The Supabase service-role key and database password were pasted into a chat transcript during provisioning and should be rotated.
  • CSP nonces. Removing 'unsafe-inline' and 'unsafe-eval'.
  • Accessibility. 19 tracked warnings, mostly labels not programmatically associated with inputs on the call-taking screen — a screen reader announces those fields with no name.
Chapter 41

Deploying

41.1 Console

Push to main; CI must be green; Vercel builds the same commit. Environment changes need a redeploy, not a restart — NEXT_PUBLIC_* values are compiled into the bundle.

41.2 Database

set -a && . ./.env && set +a
node scripts/apply-migration.mjs supabase/migrations/00NN_your_migration.sql
  • Migrations are append-only and numbered. Never edit an applied one — write the next.
  • Each file runs in a transaction, so a failure rolls the whole file back.
  • Apply before the deployment that depends on them: the app tolerates a schema newer than the code far better than the reverse.
PostgREST resolves RPCs by argument name Adding a parameter with a default to an existing function creates a second overload, and a call matching both resolves to neither. Drop the old arity in the same migration.

41.3 Responder app

eas build  --profile production --platform android   # native binary
eas build  --profile preview    --platform android   # internal APK, no push
eas update --branch  production --message "what changed"   # JavaScript only
The OTA trap — read before publishing an update An over-the-air update ships JavaScript only. If the new JavaScript imports a native module the installed binary does not contain, every handset crashes at launch. The defence is runtimeVersion, which follows the app version: bump the version whenever you add a native module, and older binaries become ineligible for the update instead of being handed something that cannot boot. Adding five native modules is exactly why the app moved to 1.1.0.

The Android FCM contract

A production Android build refuses to build without google-services.json, rather than producing an app that cannot receive a dispatch. Supply it as an EAS secret: 

eas secret:create --scope project --name GOOGLE_SERVICES_JSON \
  --type file --value ./google-services.json

The preview profile carries CRITICOM_ALLOW_NO_PUSH=1 for internal builds without push. Those are fine for testing and should not go out on shift — alerts arrive only while the app is open.

Chapter 42

Backup and Recovery

Supabase takes automatic daily backups; point-in-time recovery depends on the plan. Verify which you have before you need it. 

pg_dump "$SUPABASE_DB_URL" --no-owner --no-acl -Fc -f criticom-$(date +%F).dump

Restore into a new project first and check it, then cut over. Restoring over a live database while crews are working turns one incident into two.

Not covered by a database restoreConsequence
Storage buckets
incident-media, avatars, department-logos		Evidence photographs live here. A restore that ignores storage silently loses the attachments a case file references.
Accounts created since the snapshotRe-create with pnpm db:create-admin.
Push tokensHarmless — phones re-register on next launch.
Chapter 43

First Response

Before anything else Every procedure here is slower than the radio. If the platform is degraded and crews are waiting, put the control room on radio and paper, then fix the platform.

43.1 Triage order

#CheckInterpretation
1Admin → System StatusEach check states what it means. Start here.
2/api/health/configWhich environment variables the running build can see. Missing means absent at build time — redeploy.
3psql "$SUPABASE_DB_URL" -c 'select now()'If this fails, everything else is downstream.
4Sign in as a known accountSign-in failing while the database answers points at Auth, not data.
5Alerts in the last 15 minutesZero on a busy shift means realtime or the automation engine.

43.2 Common situations

SituationResponse
A phone is not receiving dispatchesProfile → Dispatch alerts states which of five cases applies (33.1). Realtime still delivers while the app is open in all of them.
"My update did not go through"The sync tray lists everything undelivered with its error. Queued work is held against that person's account and sends when they next have signal while signed in.
A panic fired by accidentClose the incident with a note. It is deliberately impossible to un-send.
Alert storm from a ruleDisable the rule from Admin → Automations, then inspect automation_events — repeat alerting means its claim key is wrong. Widening a threshold is the fast mitigation.
Automations not runningSee 37.4. Drive run_automations() from any external scheduler while cron is fixed.
Storage filling upScene photographs dominate. Nothing deletes them automatically, deliberately — they are evidence. Removing any is a records-retention decision.
Incident numbers look oddFormat is INC-YYYYMMDD-NNNN, sequential per department per day. Numbers before migration 0024 used a random suffix and are not sequential — history, not a fault.

43.3 Useful queries

-- Live officer emergencies
select incident_number, silo, responding_officer, location_address, incident_created_at
  from incidents
 where source = 'Responder-Panic' and status not in ('Closed','Resolved');

-- Calls waiting for a department right now
select incident_number, silo, incident_severity,
       round(extract(epoch from (now() - call_timestamp)) / 60) as minutes_waiting
  from incidents
 where status in ('New','Pending','Pending Dispatch','Pending Analysis')
 order by call_timestamp;

-- Automation health
select key, enabled, last_status, last_run_at, last_detail
  from automation_rules order by key;

-- Recent sign-ins
select user_name, silo, timestamp from audit_logs
 where action_type = 'Logon' order by timestamp desc limit 20;
Chapter 44

Engineering Standards

44.1 CI

StepCatches
pnpm lintDefect-class lint rules.
pnpm typecheckFour projects: db, api, web, mobile.
pnpm test47 tests across three packages.
pnpm buildThe production console build.
Migrations from emptyAll 28 applied in order to a throwaway PostGIS database.
Why the migration job matters A migration is the one artefact with no undo, and the sequence from nothing is what a new environment and a restore both execute. A migration that only works against the current production database has not been tested.

44.2 Testing

node --test with --experimental-strip-types. No framework, no transpile, no config — Node 22 runs the TypeScript directly. Imports use explicit .ts extensions.

SuitePins
roles.test.tsThe route matrix, including the two-desk split.
reporting/query.test.tsThat the report builder drops unknown columns, unsupported operators and invalid enum values.
automations.test.tsThat a zero threshold can never be stored.
outbox-policy.test.tsQueue ordering, collapsing, retry classification, ownership.
A pattern worth copying When safety-relevant logic is tangled with an untestable runtime, split the pure decisions into their own module and test that. outbox-policy.ts exists for this; outbox.ts re-exports it so no call site changed. Writing those tests immediately found a real defect — retry attempts were accruing while offline, so a crew in a tunnel would have a scene photograph marked failed.

44.3 Linting

pnpm lint runs biome lint, not biome check. The formatter disagrees with this codebase's consistent hand-formatting; running it produces a 150-file diff that changes no behaviour and buries every real finding. Rules the house style diverges from are off, each reviewed against its actual violations and recorded with count and reason in docs/07-ENGINEERING-STANDARDS.md.

44.4 Conventions

  • Server-action forms with uncontrolled fields.
  • Queries live in packages/api/src/<module>; pages never build queries inline.
  • logAudit on every mutation.
  • Prefer SECURITY INVOKER and let RLS scope; reach for DEFINER only where atomicity or cross-department writes demand it, and guard it.
  • Comments explain why, not what.
